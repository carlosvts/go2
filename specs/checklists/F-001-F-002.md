## H1 — dados reais com o robô parado (F-001 A12, F-002 A17)

Pré-requisitos: robô de pé (`balance_stand`), parado, de frente para uma parede lisa. API subida com o log `api-h1.log`.
Segurança: o robô não anda nesta etapa. Controle à mão mesmo assim.

Passos:
1. Pôr o robô em equilíbrio:
   `curl -X POST localhost:8000/commands/posture -H 'content-type: application/json' -d '{"cmd":"balance_stand"}'`.
   Esperar ele estabilizar.
2. Medir com trena a distância do **centro do robô** até a parede, na horizontal. Anotar `d_trena`.
3. Diagnóstico rápido (10 s): `uv run python scripts/ws_lidar_client.py --seconds 10`.
   - Chegam frames? Anotar frames/s e `n_points`.
   - **Se nenhum frame chegar:** anotar isso. Passo opcional, só com aprovação da equipe: publicar `"on"` em `rt/utlidar/switch`. A api não expõe isso; é uma hipótese do F-001 (H1.4). Depois, repetir este passo e anotar o resultado. Se ainda não chegar nada, **pare aqui** e traga o log.
4. Gravar 60 s, com o visualizador aberto ao mesmo tempo, se quiser (cabe com `GO2_LIDAR_MAX_CLIENTS=2`):
   `uv run python scripts/record_lidar.py --out ../gravacoes/h1-parado --seconds 60 --api-commit <commit>`.
   Anotar o código de saída (0 esperado) e a última linha impressa.
5. Do `telemetry.jsonl`, copiar o `data` de 3 frames `lidar_metrics` (início, meio e fim): `rate_hz`, `interval_ms`, `n_points`, `compressed_bytes`, `decode_ms`, `pipeline_ms`, `resolution`, `origin`, `dropped_*`, `decoded`, `active`. Pode colar as linhas inteiras.
6. Contar no `telemetry.jsonl` quantos `lidar_pose` e `lidar_state` chegaram (`grep -c '"lidar_pose"'`). Se chegaram, colar um de cada. Se o `data` vier com `{"base64": ...}`, registrar isso.
7. Abrir 3 frames de `lidar/` (snippet do `ws-lidar.md`):
   ```python
   import numpy as np
   p = np.frombuffer(open(f, "rb").read(), "<f4", offset=40).reshape(-1, 3)
   ```
   Em cada um: `n_points` (`len(p)`), e se a nuvem mostra o lab ao plotar.
8. **A12:** medir na nuvem a distância do robô até a parede. Registrar como fez: onde o robô fica na nuvem (perto de `(0,0,0)`? perto do `origin`?) e quais pontos foram a parede. Anotar `d_nuvem` e a `resolution` do frame.
9. Tamanho do diretório gravado (`du -sh ../gravacoes/h1-parado`): ________. Isso informa o `--max-mb` futuro.

Registrar:
- frames/s do passo 3;
- código de saída e resumo do gravador;
- as 3 linhas de `lidar_metrics`;
- contagens e exemplos de `lidar_pose`/`lidar_state`;
- `d_trena`, `d_nuvem`, `resolution`;
- o tamanho em disco;
- um print da nuvem;
- o `api-h1.log`.

Passa se:
- **F-001 A12:** chegam frames com `n_points > 0` e `|d_nuvem − d_trena| ≤ 0,05 m`. A meta é 0,01 m; registrar o erro medido de qualquer forma.
- **F-002 A17:** `lidar_metrics` com `received > 0` e `active: true` na maior parte das janelas (anotar quantas de quantas), e os `.bin` abertos com `n_points > 0`.

4. Medir com trena quanto o robô andou: ________ m.
5. Depois da gravação:
   - o `origin` dos frames mudou ao andar? De quanto?

## H3 — interferência no `stop` e no `move` (F-001 A13 e A14, F-002 A18)

É a etapa mais arriscada: 20 movimentos, com `stop` no meio. Supervisão total.

Pré-requisitos: robô em `balance_stand`, área livre (~2 m à frente), parada de emergência digitada, controle à mão. Câmera filmando de lado, com o robô **e** a tela do terminal do `curl` no quadro.
Segurança: se o robô não parar com o `stop` da api, use o controle. Se isso acontecer, **interrompa a etapa** e traga o vídeo. Não continue as repetições.

### Configuração da medida

- `stop` (A13): para cada repetição, medir no vídeo o tempo entre o quadro em que a resposta do `curl` de `stop` aparece no terminal e o quadro em que as patas param. Anotar o fps da câmera: ________. A resolução da medida é 1/fps.
- `move` (A14): o log DEBUG de cada etapa vai para `scripts/move_jitter.py`.

### H3a — linha de base (sem LiDAR)

1. **Reiniciar a api** (Ctrl+C e subir de novo) com o log em `../api-base.log`. **Não** conectar nenhum cliente de LiDAR nem de telemetria desde o boot. O gravador e o visualizador ficam fechados.
2. `balance_stand` (comando do H1.1).
3. Repetir 10 vezes:
   1. `curl -X POST localhost:8000/commands/move -H 'content-type: application/json' -d '{"vx":0.3,"vy":0,"vyaw":0,"duration_s":2}'`;
   2. ~1 s depois, `curl -X POST localhost:8000/commands/stop`;
   3. reposicionar o robô, se preciso, só com o controle ou com mais `move`, sempre com `balance_stand` antes.
4. Se a conexão com o robô cair durante uma repetição (o log mostra `Conexão com o Go2: disconnected`), **descartar** essa repetição e anotar. A reconexão trava a api por motivo alheio à feature.

### H3b — carga da sessão (2 clientes de LiDAR + 1 de telemetria)

1. Reiniciar a api com o log em `../api-carga.log`.
2. Abrir o visualizador em `/ws/lidar` e começar a gravar, por tempo suficiente para as 10 repetições:
   `uv run python scripts/record_lidar.py --out ../gravacoes/h3-carga --seconds 600 --api-commit <commit>`.
   Isso ocupa 1 vaga de `/ws/lidar` e a de `/ws/telemetry`.
3. `balance_stand` e as mesmas 10 repetições do H3a, com a mesma regra de descarte.
4. Parar o gravador (Ctrl+C ou fim do tempo) e anotar o código de saída.

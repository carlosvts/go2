# Roteiro hardware-only — F-003 (`/ws/video`)

Spec: [`F-003`](../features/F-003-ws-video.md). Contrato: [`ws-video.md`](../contracts/ws-video.md).
Código: branch `feat/api-completa` (contém a F-003 com o JPEG pelo PyAV; commit `3394526` ou posterior). Anote o commit que rodou.

Critérios cobertos:

| Critério | O que é | Parte |
|---|---|---|
| A15 | 60 s com 1 cliente: toda janela de 1 s com ≥ 1 frame; 100% dos JPEGs decodificam; cada buraco no `seq` tem descarte correspondente no `video_metrics` | H1 |
| A16 | Depois do último cliente sair: `video_metrics` com 0 quadros lidos a partir de 2 s depois do `False`, por 30 s | H1 |
| A17 | `stop` com vídeo ativo (LiDAR desligado): mediana até +0,2 s sobre a mediana da linha de base; nenhuma repetição acima de +0,4 s | H2 |
| A18 | `move` com vídeo ativo: p99 do desvio ≤ p99 da linha de base + 10% do período; máx. ≤ 2× o período | H2 |

O resto do H1 (resolução, taxa, qualidade da imagem, atraso, indicador no robô) é registro para as hipóteses, sem passa/falha. A avaliação da imagem é sua, em texto.

Este roteiro **não** declara nada verificado. Quem testa é a equipe; os resultados voltam para mim (skill `hardware-checklist`), que os anoto na spec sem arredondar.

**Ordem:** H1 (robô parado) → **você decide** `GO2_VIDEO_MAX_FPS` e `GO2_VIDEO_JPEG_QUALITY` → H2 (robô andando) com esses valores. O H2 só vale para os valores usados nele.

## H1 — câmera real com o robô parado (A15, A16 e hipóteses)

Pré-requisitos: robô de pé (`balance_stand`) e parado, api recém-iniciada com o log `api-h1.log`, **nenhum cliente de vídeo aberto ainda**.
Segurança: o robô não anda nesta etapa. Controle à mão mesmo assim.

Passos:
1. **O robô manda vídeo sem pedir?** Com a api recém-iniciada e nenhum cliente, esperar 30 s e olhar o log:
   - aparecem linhas `video_metrics`? Elas só saem quando existe track;
   - se aparecem, o campo `read` é 0 ou maior que 0?

   Anotar. **Se `read > 0` sem cliente nenhum, o H2 não roda** (a linha de base fica contaminada; ver Segurança da F-003). Siga o H1 e traga o log.
2. Abrir o `video_viewer.html` e conectar. Enquanto conecta, **olhar e escutar o robô**: alguma luz, som ou movimento muda quando a câmera liga? Anotar. No visualizador, anotar a sequência de estados (`starting` → `streaming`?) e se a imagem aparece.
3. **A15.** Fechar o visualizador. Rodar o cliente de diagnóstico por 60 s:
   `uv run python scripts/ws_video_client.py --seconds 60 | tee ../video-h1.txt`.
   Anotar de algumas linhas: frames/s, resolução, KiB mín./médio/máx., `não decodificaram`, `buracos no seq`, atraso médio e intervalo de `media_time`.
   No mesmo intervalo, anotar a CPU da api (`top`, processo do uvicorn): ________ %.
4. **Se ficar em `stalled`** (nenhum quadro): anotar e copiar do `api-h1.log` as linhas perto de `Câmera ligada.` (resposta do `disableTrafficSaving`, `video_metrics`, aviso de câmera sem quadros). Fechar e reabrir o cliente e anotar se a imagem chega. Se não chegar, **pare aqui** e traga o log.
5. **Qualidade da imagem.** Com o visualizador aberto, avaliar em texto: nitidez, cor, campo de visão, comportamento com a luz do lab (contraluz, sombra), se dá para reconhecer uma pessoa e objetos a 1 m, 3 m e 5 m.
6. **A16.** Fechar **todos** os clientes (visualizador e diagnóstico). No log:
   - conferir a linha `Câmera desligada.` e anotar a hora;
   - copiar as linhas `video_metrics` dos 30 s seguintes.

   Depois, reabrir o visualizador e conferir que a imagem volta (estados `starting` → `streaming`).
7. **Atraso câmera → tela.** Abrir um cronômetro com centésimos na tela de um celular. Pôr o celular na frente da câmera do robô, ao lado do monitor com o visualizador, e fotografar os dois juntos. A diferença entre o cronômetro real e o que aparece no visualizador é o atraso. Repetir 5 vezes.
8. **Gravador** (só com as pessoas avisadas): `uv run python scripts/record_video.py --seconds 30 --api-commit <commit>`.
   Anotar o código de saída (0 esperado), o diretório criado em `gravacoes/` e se os `.jpg` abrem.
9. **Qualidade × tamanho.** Para cada valor de `GO2_VIDEO_JPEG_QUALITY` abaixo:
   1. trocar no `.env` e reiniciar a api;
   2. rodar o passo 3 por 20 s;
   3. anotar KiB médio, frames/s, CPU e a impressão da imagem.

   Se a taxa do passo 3 for alta e a CPU também, repetir uma vez com um `GO2_VIDEO_MAX_FPS` menor que a taxa medida.

## H2 — interferência no `stop`/`move` (A17, A18)

Não rodar se o H1.1 mostrou o robô mandando vídeo sem cliente.

Pré-requisitos: robô em `balance_stand`, área livre (~2 m à frente), parada de emergência digitada, controle à mão, LiDAR desligado (`GO2_LIDAR_MAX_CLIENTS=0`, `GO2_TELEMETRY_MAX_CLIENTS=0`). Câmera **do celular** filmando de lado, com o robô **e** a tela do terminal do `curl` no quadro.
Segurança: ninguém dentro da área durante o `move`. Se o robô sair da linha ou se aproximar de algo, parada de emergência ou controle remoto, sem esperar a repetição terminar.

Como medir:
- **`stop` (A17):** para cada repetição, medir no vídeo o tempo entre o quadro em que a resposta do `curl` de `stop` aparece no terminal e o quadro em que as patas param. Anotar o fps da câmera do celular: ________. A resolução da medida é 1/fps.
- **`move` (A18):** o log DEBUG de cada etapa vai para `scripts/move_jitter.py`.

Passos:
1. **Linha de base.** Reiniciar a api com o log `api-base.log` e **não abrir nenhum cliente de vídeo desde o boot**.
2. 10 repetições, voltando o robô ao ponto de partida entre elas:
   1. `curl -X POST localhost:8000/commands/move -H 'content-type: application/json' -d '{"vx":0.3,"vy":0,"vyaw":0,"duration_s":2}'`;
   2. ~1 s depois, `curl -X POST localhost:8000/commands/stop`.
3. **Com vídeo.** Reiniciar a api com o log `api-carga.log`, com os valores decididos entre H1 e H2. Abrir **2 clientes** de `/ws/video`: o visualizador e `uv run python scripts/ws_video_client.py --seconds 900`. Conferir que o visualizador mostra `streaming`.
4. Repetir o passo 2 (10 repetições).
5. Se a conexão com o robô cair numa repetição (log `reconnecting`), **descartar essa repetição** e anotar: a reconexão trava o loop por motivo alheio à feature.
6. Comparar os reenvios do `move`:
   `uv run python scripts/move_jitter.py ../api-base.log ../api-carga.log --rate-hz <GO2_MOVE_RATE_HZ>`.
